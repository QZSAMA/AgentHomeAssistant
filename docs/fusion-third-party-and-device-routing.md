# Fusion 第三方扩展与同 SSID 按设备分流

日期：2026-11-05。状态：**用户已批准下文方案A：同一局域网、不划分VLAN、少量终端手动选用OpenWrt。** 本文保留功能调研，正式执行以[批准版设计](superpowers/specs/2026-11-05-home-device-rule-routing-design.md)、[实施计划](superpowers/plans/2026-11-05-home-device-rule-routing.md)和[验收单](validation/home-device-rule-routing.md)为准；尚未配置家庭设备，终端参数及双栈行为待验证。

## 1. 本轮明确的接入范围

用户提出按需使用规则服务，并明确 **2.4GHz 共用一个 SSID，按设备区分**：

- 智能家居设备继续走稳定的普通网络与局域网，不应因 J3455 规则服务停机而失去基础网络。
- 需要规则的手机或平板在该 2.4GHz SSID 下使用 J3455/OpenWrt。
- 5GHz、可实际启用的 6GHz 日常网络走 Fusion；需要时由终端自己的客户端工具处理。

这调整了此前“所有联网设备统一经过规则服务”的目标；旧全屋网关/DHCP迁移继续暂停。**用户随后明确：不需要 VLAN，所有设备必须属于同一套共同网络。** 当前方案保留单一家庭 LAN/网段，2.4GHz、5GHz、可用的6GHz及有线设备接入同一网络，不采用 PPSK/VLAN 分网，也不启用阻断家庭互访的访客或客户端隔离。指定终端可单独设置 OpenWrt 网关与规则 DNS；这不改变它与其他设备同网段的关系。既有 Fusion、交换机和 AP 采购基线保留。

频段决定无线接入方式，默认网关决定出网路径；一个 2.4GHz SSID 内可以有不同网关的设备。2.4GHz 与 5/6GHz 若要保存不同的终端网络配置，应使用不同 SSID；不能指望同名网络从一个频段漫游到另一个频段就自动更换网关。

## 2. Fusion 的第三方能力边界

依据 [Fusion 软件架构说明](https://support.omadanetworks.com/us/document/137773/)及 [Fusion Gateway User Guide REV1.0.1](https://support.omadanetworks.com/us/document/123305/)：

| 类别 | 已确认内容 | 对本项目的意义 |
|---|---|---|
| 内置应用 | 普通 Fusion 支持 Network Application；Guard 应用属于支持它的 Pro/Max 型号 | 应用管理页不是通用第三方软件商店 |
| 外部服务对接 | 手册提供 Webhooks、SMTP、第三方 DDNS、外部 DNS、RADIUS 等功能 | 可连接外部系统，不代表在 Fusion 内运行它们 |
| 自行安装规则工具或容器 | 本轮未找到原厂支持安装 OpenClash、Mihomo、mosdns 或 Docker 的文档 | 仍将规则工具规划在 J3455/OpenWrt，不能预设 Fusion 可安装插件 |
| SSH 与维护入口 | 有设备管理用途说明 | 不能由存在 SSH 推定可安装任意软件、拥有系统权限或升级后仍兼容 |

手册“OS & Applications”为平台部分印刷页 19 / PDF 页 562，其中 Install/Uninstall 仅对 Guard 应用说明；Webhooks 为平台部分印刷页 23 / PDF 页 566。手册还涉及 Open API，但未在本轮确认 Fusion 全部 API 能力与第三方集成兼容，不据此作进一步承诺。

## 3. 三种实现方式

### A. 少数终端手动指定网关：已批准采用

保持普通家庭 LAN，不增加针对这些设备的 VLAN。Fusion 是该 LAN 唯一 DHCP；OpenWrt 接同一 LAN，使用查重后的固定管理地址，关闭面向该 LAN 的 DHCP 和路由通告。

| 设备/接入 | 网关 | DNS | J3455 停机后的影响 |
|---|---|---|---|
| 智能家居，2.4GHz 共用 SSID | Fusion，自动取得 | Fusion 的独立普通解析 | 基础路由、地址服务和普通解析不依赖 J3455 |
| 指定手机/平板，同一个 2.4GHz SSID | 在该 Wi-Fi 配置里手动指定 OpenWrt | OpenWrt 规则解析 | 本组外网可能不可用；切换日常 SSID可恢复普通路径 |
| 手机/平板，另一个日常 5/6GHz SSID | Fusion，自动取得 | Fusion | 普通网络不依赖 J3455；客户端工具只作用于启用它的终端 |
| 有线 Apple TV 等终端 | 默认 Fusion | Fusion | 不由无线频段决定规则；是否使用客户端工具另按设备软件核验 |

本方式无需 Fusion 具备“按网站指定 LAN 下一跳”的策略能力，也无需引入全屋合成地址段路由。对于少数需要规则的终端，管理成本较低。

手机/平板的手动 IPv4 设置一般还需填写固定地址和子网掩码；地址须避免与 DHCP 分配冲突。应在 Fusion 留出或保留地址，并记录该 SSID 下的实际设备标识。若用 MAC 做保留或识别，应使用该网络稳定的私有地址模式，不能任意轮换后仍期待原规则命中。

**单独改 IPv4 网关不等于 IPv6 也进入 OpenWrt。** 必须核验指定终端的 IPv6 路径和实际应用行为；不能为少数终端规则而整体关闭智能家居所需的本地 IPv6/Thread。

J3455 停机后 AP 仍可能正常广播 Wi-Fi，手机不会必然自动切到日常 SSID。因此本方案隔离的是其他设备的故障影响，**没有保证正在使用 OpenWrt 的终端无感恢复**。此故障边界已纳入用户批准的方案；具体切回操作与恢复时间仍需现场验收。

### B. 历史比较：PPSK/VLAN 分组已排除

**用户已明确不划分 VLAN，本节仅保留功能调研，不作为当前实施候选。** PPSK 本身也可仅用于多密码认证，但本项目没有新增此项需求。

Fusion 专用手册印刷页 276–278 / PDF 页 311–313 确认 PPSK 可设置独立密码、可选 MAC 绑定与 VLAN Assignment。[官方配置指南](https://support.omadanetworks.com/us/document/113988/)也演示同一 SSID 下，不同密码使设备加入不同 VLAN。

因此可以保持相同 Wi-Fi 名称：智能家居使用普通组密码，手机/平板使用规则组密码，再通过不同网络的地址服务分配网关。这里按密码/可选 MAC 识别设备，并非仅根据频段自动判断用途。

代价是需要配置和验证 VLAN 从 AP、各级交换机到 J3455/PVE 的完整路径，并处理跨网段的 HomeKit、AirPlay、发现与访问。具体 AP 型号、硬件版、固件及认证组合仍需兼容性核验。先比较不依赖外部 RADIUS 的方式，不能把智能家居的唯一认证服务放在 J3455 上又声称不依赖它。

PPSK 是“同一个名称、可使用不同密码”，不能将其表述为“同名同密码，仅在 Fusion 勾选设备就自动分网”。本节分网方案已从当前范围排除。

### C. Fusion 在同一 LAN 内按设备下发不同网关：仍待确认

手册印刷页 104–105 / PDF 页 139–140 确认 **按 LAN 网络设置** DNS 和默认网关，支持手动网关；印刷页 116–117 / PDF 页 151–152 提供 **按设备保留 IP**。

保留页的概述提及支持设备的 DHCP Options，但其示例表单与[官方地址保留教程](https://support.omadanetworks.com/us/document/13075/)没有明确展示按单台设备覆盖默认网关/DNS 的完整配置。不能把“固定 IP”或“整个 LAN 可自定义网关”当作已确认的逐设备网关功能。

因此，目前不能向用户承诺在 Fusion 中按 MAC 配置网关白名单就能完成本方案。若实机支持并确认对应 DHCP 选项覆盖行为，再将它作为减少终端手工配置的改进。

## 4. 智能家居稳定性的边界

- 不浏览网页不等于不需要互联网；设备可能使用云端控制、远程访问、时间同步、账户认证与更新。默认给它们普通 Fusion 出口，不直接设成全组禁止外网。
- 若普通手机、Apple 家庭中枢和智能家居保留同一家庭 LAN，可减少跨网段发现配置。不要把家庭设备 SSID 当作禁止内网访问的访客网，也不要未经验证开启客户端隔离。
- 局域网通信不必经过默认网关的前提是处于同一可互通网段且访问真实局域网地址；名称解析、隔离规则和实际应用依赖仍需核验。
- 若 Home Assistant 将来运行在 J3455 上，宿主停机仍会使其自动化与服务停止。网络独立不等于该宿主上的所有智能家居功能也独立。
- 终端工具需保留局域网访问；Apple TV 的具体可用工具取决于型号、tvOS、商店地区和应用支持。有线接入不属于 Wi-Fi SSID 分组。
- 6GHz 的地区、AP 与终端支持仍沿用此前核验边界；本方案不改变其可用性，日常网络以可用的 5GHz 为基础。

## 5. 批准与执行状态

按已批准范围，保留 **同一家庭 LAN/网段、Fusion 唯一 DHCP 与独立普通解析**，OpenWrt 关闭该 LAN 上的 DHCP/RA，仅服务主动选用它的少量终端。采用终端手动设置网关和规则 DNS；若以后确认 Fusion 支持逐设备 DHCP 网关覆盖，再作为同网段内的管理改进。**不采用 PPSK/VLAN 分网，不把普通终端的默认网关或 DNS 全局改到 J3455。**

采购与物理接线保持，指定终端故障时手动切日常SSID或恢复自动网络配置。执行顺序、参数登记、双栈限制及故障检查已整理至[现行实施计划](superpowers/plans/2026-11-05-home-device-rule-routing.md)和[现行验收单](validation/home-device-rule-routing.md)。所有现场检查仍为 `not_run`，本文件不是已完成的部署记录。
