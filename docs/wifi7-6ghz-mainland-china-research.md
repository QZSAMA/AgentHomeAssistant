## 摘要

**技术上存在成功连接 6GHz 的公开自述和截图，但不能据此认为中国大陆已经开放普通家庭 6GHz Wi-Fi，或保证购买美国版 EAP775-Wall 就能使用。** 本次查到的最具体记录，是 Chiphell 用户于 2026-02-26 发布的 BE200 截图：驱动 `24.20.0.4`、Wi-Fi 7、WPA3-Personal、实际网络波段 `6GHz（85）`、聚合链路速率 `5764/5764Mbps`。它证明该截图呈现了 6GHz 连接，而非只出现 Wi-Fi 7 图标；但测试地点仅有大陆主题语境，AP 精确型号、固件和长期复现记录缺失，不能升级为本项目已验证能力。[8] [9]

关键判断如下：

| 用户关心的问题 | 调研结论 | 把握与限制 |
|---|---|---|
| 大陆家用能否合规开启 6GHz？ | 本次未发现面向普通住宅 WLAN 开放 6GHz 的有效政策依据；项目不应将其列为可启用的合规基线 | 已核 WLAN 管理通知、6GHz 划分发布及 Apple 官方地区说明；不是穷尽所有特许试验许可的法律意见 |
| 是否绝对不能发射或连接？ | 不是。公开资料中有特定硬件/驱动/地区配置下的成功自述，部分有实际 6GHz 字段截图 | 同一讨论中也有看得到却不能连接、仅跑5GHz、后续关闭的反馈 |
| 苹果设备能否通过美版 AP 获得 6GHz？ | 不能承诺。Apple 2026 年官方文档明确：中国大陆 Wi-Fi 6E 不可用，Wi-Fi 7 支持但不能使用 6GHz | 不能以海外购机、改语言/Apple ID 或一条 Mac mini 自述推翻正式支持边界 |
| EAP775-Wall ×3 / EAP772 ×1 是否已找到大陆成功方案？ | **未找到足以复现、与本项目型号和版本对应的大陆成功证据** | EAP775-Wall 美国硬件三频已确认；Omada 通用配置文档不是大陆解锁保证 |
| 能否给出启动方法？ | 可以给出厂商正常配置流程，以及网友声称的地区/驱动方法及适用限制 | 正常流程仅适用于当地许可、设备与终端均支持的场景；非官方方法不纳入家庭生产配置 |

建议保留用户暂选的三台 EAP775-Wall 和大厅一台 EAP772 候选，但将 6GHz 标为“**不计入大陆部署保证能力；合规前提未满足，实机未验证**”。先满足合法的 2.4/5GHz、AP 2.5G 有线回程与电竞房 Mac/NAS 本地 10G 目标；若购买价值依赖 6GHz，应先暂停批量下单，取得地区认证及厂商书面支持条件，而不是把问题留到装修完成后解决。

## 1. 研究范围与证据标准

本报告针对中国大陆住宅，不把香港、澳门、台湾或海外合法使用经验直接外推。对象是暂选美国版EAP775-Wall面板×3、EAP772吊顶×1，兼顾Apple、Intel等终端。**有线方案引用更新（2026-10-14）**：以[网络拓扑v1.2](network-topology.md)为准，四条Cat6A主干均2.5G；主卧/次卧仅 Wall AP，由中央匹配 PoE 直供，取消卧室设备箱/独立交换机，有线终端接 AP 的 1×2.5G + 3×1G 下联；电竞房/大厅保留设备箱和交换机，电竞房ES210XPP-M2单台，Mac RJ45/NAS SFP+本地10G，NAS/J3455接电竞房箱外设备位。仅同步上下文，不改变本报告6GHz证据、合规结论或品牌方向；不沿用v1.0中央NAS布局或v1.1四房间交换机布局。

采用“监管→AP→终端→连接证据→长期运行”的链条分析，先形成[研究框架](research/wifi7-6ghz-mainland-framework.md)，再读取官方说明及论坛原帖。没有实际操作 AP、刷固件、修改国家码、安装驱动或进行射频测试。网页随时可能更新，历史版本是否仍能复现不得仅按发帖日期推定。

| 等级 | 本报告采用的含义 | 不能由此推出的结论 |
|---|---|---|
| A：官方正文 | 政府发布/转载正文，或厂商正式产品、支持说明 | 国外产品参数不是大陆许可；官方通用步骤不是本机验收 |
| B：带具体参数的第一人称案例 | 读到原帖，型号/版本较具体，或直接检查了实际频段截图 | 截图真实性、地点与完整环境仍未由独立实验验证 |
| C：不完整自述或转述 | 读到讨论，但缺频率、版本、地点等关键条件 | 不作为可复制成功方案，不统计“成功率” |
| D：发现线索 | 搜索摘要或未能读取的页面 | 不引用为已经完整核验的正文 |

以下五种“启动成功”必须分开：菜单出现6GHz、AP发出6GHz信号、终端发现SSID、终端确实在6GHz关联、重启/升级后长期稳定。再加上独立的当地合规条件，才可能成为可部署方案。SSID名称包含“6G”、Wi-Fi 7图标、MLO客户端列表以及很高的链路速率，均不能单独通过这一判断。

## 2. 中国大陆的监管与频段边界

| 频段/事项 | 已读依据 | 本项目含义 |
|---|---|---|
| 2,400–2,483.5MHz | 工信部无〔2021〕129号明确可用于宽带无线接入（含WLAN）等 | 仍须符合设备型号核准、射频与使用要求，不是任意海外发射参数均可使用 |
| 5,150–5,350MHz | 同一通知明确WLAN等用途，且仅限室内、不包括汽车内；其中5,250–5,350MHz有TPC/DFS要求 | 采用实际所在地合规信道/功率，不关闭规定要求的DFS |
| 5,725–5,850MHz | 同一通知明确包括WLAN等用途 | 正常5GHz设计仍需按具体SKU和当地要求验收 |
| 6,425–7,125MHz | 2023年新版频率划分发布说明，原文为“全部或部分频段划分用于IMT（含5G/6G）系统” | 不能将其视为家庭Wi-Fi开放；也不能把这句话改写为整个5,925–7,125MHz都只允许同一业务 |
| 5,925–6,425MHz（部分地区从5,945MHz起） | 不能由上6GHz的IMT新闻反推下6GHz获准WLAN；本次未取得大陆普通住宅在该段的开放依据 | “没被这则IMT新闻覆盖”不等于“免许可可用”；不把欧洲/香港等地区规则移植到大陆 |
| Wi-Fi 7 / IEEE 802.11be 核准 | 检索到湖南省工信厅2023-12-21转载的技术要求，其摘要列2.4/5GHz工作范围；原页面本次连接失败，列D级补充线索 | Wi-Fi 7标准与频率许可是不同维度，不依赖这条未读全文的材料作唯一结论 |
| 2026年“6GHz获批”新闻 | 中国科技网转载央视财经正文，讲的是蜂窝6G试验频率许可和技术试验 | 不是Wi-Fi 6E/Wi-Fi 7的家庭6GHz开放通知 |

来源：[工信部无〔2021〕129号，北京市政府转载][1]、[2023年频率划分发布，中国政府网][2]、[2026年6G试验报道][3]、[Wi-Fi 7核准线索][12]。

监管层面的关键区别是“频率划分”“某类设备/业务的使用规则”“设备型号核准”并不相互替代。美国FCC认证、产品可以买到、室内低功率运行、甚至终端已经连上，都不能自动产生大陆的使用许可。129号通知对指定2.4/5GHz设备的台站执照豁免也不能扩展成6GHz的一般豁免。本次没有发现面向普通家庭WLAN的6GHz开放依据，结合Apple截至2026年的正式地区说明，足以支持“不把大陆6GHz列作本项目可用基线”的工程决定；但不应伪装成对所有科研试验、专用链路及个案许可的穷尽法律判断。若确有受控测试需求，应先向当地无线电管理机构或有资质实验室核清条件，自备屏蔽箱、调低功率或在家中测试本身不是当然授权。报告不采信论坛“没人管”“最多罚多少”的安慰性表述，也不从未经核验的帖子计算法律后果。

### AFC 不是中国大陆的“6GHz开通服务”

[Omada AFC 官方说明][10]（页面日期2026-08-20）明确区分标准功率与室内低功率：标准功率设备通过自动频率协调保护既有业务，低功率室内设备与其要求不同。文档称当前其AFC服务支持美国、加拿大，其他地理位置激活会失败；室内AP可利用周边SSID辅助定位。因此不能将“海外IP/VPN”当作可靠的位置或许可替代，也不能说所有6GHz室内AP都必须先通过AFC才能工作。

对本项目尤其值得注意：该页“已支持”名单包含 **EAP772 v2.0（US）**，而非只列室外型号；未列EAP775-Wall。它还说明示例中室外AP关闭AFC会停止6GHz，其他型号进入低功率模式。**这一国外产品行为描述不代表在中国大陆低功率运行合法，也不能据名单缺项断言EAP775-Wall永远不会支持AFC。** 大厅采购必须记录硬件版本及固件，不可把EAP772各版视为完全一样；墙面机也不可误用EAP775-Outdoor的说明。AFC、AP监管域和客户端地区策略是不同环节，任一环节设置成功都不能保证整条链路通过。

厂商文档和用户案例呈现的不是一个统一“开关”，而是一组相互独立的约束。最容易造成错误采购的是只核验AP三频硬件，却忽略常用终端的正式支持区域；对于以Apple Home和苹果终端为主的住宅，这个差异比单次测速更重要。既有方案中Mac使用10G有线，不需要用6GHz补救服务器连接；智能家居则需要稳定的2.4GHz/Thread/Zigbee链路。即使未来某台电脑在特殊环境下连上6GHz，仍不能据此把家庭中枢或传感器迁入同一假定能力。对无法取得逐型号资料的环节，正确状态是“待验证”，不是套用另一个品牌的国家码步骤、推定换网卡必成功，或把AFC失败简单归因于网络代理。

针对`EAP775-Wall + 6GHz + China`的型号专项检索，返回主要是销售页、地区官网和非对应讨论；没有找到同时具备大陆地点、硬件版本、固件/控制器、终端和实际频率证据的EAP775-Wall记录。**未找到不等于证明不存在**；本报告不声称全网穷尽。EAP772、UniFi或Archer/GE800等经验，也不能自动替代本项目775-Wall的验证。

## 5. 启用方法：正常流程与非官方声称方法

### 5.1 有依据的 Omada 正常配置流程

前提是**实际运行地点允许相应6GHz使用、具体设备SKU/固件获支持、客户端也允许在当地使用**。当前中国大陆住宅尚未满足本报告的合规前提，以下作为知识与未来验收流程，**不是本项目现在应执行的开通指令**。菜单依据[Omada官方EAP783示例][6]，775-Wall/不同控制器版本可能不同；不存在本次已证实的“775大陆一键解锁”。

1. 记录AP型号、国家SKU、硬件/固件版本、控制器版本和客户端系统/驱动；使用对应地区的官方固件，管理站点如有国家选择应与真实所在地一致。若地区不允许/没有6GHz选项，停止并向厂商核实，不把伪造所在地当正常配置。
2. 官方示例在站点 `Settings → Wireless Network → WLAN` 创建或编辑无线网络；填写SSID，在 `Band` 勾选 `6GHz`，配置安全类型/密码并应用。
3. 首次诊断可建立独立、广播的6GHz测试SSID，以便明确关联频段；个人网络选择 `WPA3-SAE`，`PMF`为强制。官方也列Enhanced Open和WPA3-Enterprise，但本项目个人家庭测试不采用无口令的Enhanced Open作为默认方案。
4. 优先使用设备在该地区允许的PSC（首选扫描信道），不要一开始强行启用Non-PSC。官方示例的 `Devices → EAP → Config → Advanced → 6GHz → Non-PSC Channel` 是可选扩展，不是打开6GHz的必要步骤；具体路径不保证适用于所有版本。
5. 先验证单频6GHz能否关联，再评估MLO与多AP漫游。此顺序是本报告的隔离变量建议，不是厂商承诺MLO能解除地区限制。测试信道/带宽只能从该地区允许项中选择，不以320MHz为起步必选值。
6. 在AP客户端详情和终端两侧检查**实际频段/频率、信道、BSSID、带宽和每条MLO链路状态**。关联成功后，再做有线测试服务器的局域网吞吐与稳定性测试；不要只看公网Speedtest或SSID名字。
7. 如不能发现，依次核当地监管/客户端支持、SSID广播、PSC、安全配置、OEM支持及驱动；如修改过安全模式，按官方建议在终端忘记网络后重新关联。保留独立2.4GHz兼容SSID，避免给旧IoT强加WPA3/PMF要求。

[Omada指南][6]为兼容性建议分开2.4/5与6GHz的SSID，而[Apple支持文章][13]建议各频段统一SSID，并指出分开命名可能使Apple设备将网络视为“有限兼容性”。两者建议并不完全一致：本报告的独立SSID只用于隔离诊断，不能作为Apple生产网络的默认设计。若将来满足当地许可，应以Apple的同名多频段建议为起点验证主网络，再按实际终端与漫游结果调整；旧IoT兼容网络可单独规划，不能把诊断配置当永久最优。

### 5.2 网上声称的“启动/解锁”方法及边界

| 方法类别 | 已查到的具体声称 | 可以合理得出的结论 | 不采用为本项目操作方案的原因 |
|---|---|---|---|
| AP地区改香港/美国 | C3称UniFi设香港后Mac mini能连接 | 某些系统可能暴露地区设置，技术行为可能改变 | 在大陆填其他地区不能产生当地许可；没有775-Wall逐版本方法；同品牌有失效自述 |
| 更新特定网卡驱动 | C1的23.160.0.4、C2截图24.20.0.4 | 驱动版本与结果有关，有具体历史记录 | 不是所有Intel/OEM适用；不固定旧驱动作为安全/维护策略，也不保证后续版本不改变 |
| 周边美区SSID影响地区识别 | C2作者称以OpenWrt增加美区SSID后可用；V2EX有类似讨论 | 是已公开的作者声称机制 | 未给完整数量/型号/配置，不能凭空补成教程；改变周边监管广播不改变合法所在地，不能操作他人AP |
| 休眠/唤醒时机 | C2称近期驱动在休眠启动后能连接6GHz SSID | 地区检测/初始化可能与状态变化有关，机制未由本次验证 | 不等于冷启动、断电、漫游和系统升级后可靠，不适合家庭基础设施依赖 |
| 刷海外固件、Root、改监管数据库/注册表 | V2EX有讨论和转述，没有本项目机型完整证据链 | 存在这些尝试方向，不能确认每种都有效 | 有型号不匹配、变砖、丧失保修、更新失效和安全风险；本报告不编造寄存器、国家码命令或固件包 |
| VPN、改Apple ID/系统语言 | 本次未取得它们单独使本项目终端在大陆连上6GHz的可靠证据 | 不能把网络出口或界面地区等同无线监管域 | Apple仍有官方地区限制，Omada AFC还涉及地理定位；不是已验证方案 |

本报告已经给出公开案例实际声称的方法和版本，而没有把证据不足的操作扩写成“照做必成功”。这是技术可复现性上的边界，不是否认研究这些机制的价值。家庭方案的评价标准包括停电重启、固件维护、手机系统更新以及对既有无线业务的合规影响，偶发成功只覆盖其中一个时点。在获得许可的地区或符合条件的实验室，可依据官方流程和版本记录开展验证；在本项目大陆住宅中，当前可执行的稳妥方案是保持真实地区及合规频段，将6GHz排除在承诺功能之外。不能通过降低安全配置、伪装国家码、反复回退驱动等操作，把一个缺少监管前提的功能变成“已经解决”的采购结论。

## 8. 结论

中国大陆6GHz Wi-Fi的“能不能启动”没有一个能同时覆盖法律、AP、终端和稳定性的单一答案。公开材料支持“特定组合存在技术成功自述，且有实际6GHz字段截图”，不支持“大陆普通家庭已经获准普遍使用”，也不支持“美国版EAP775-Wall配苹果终端必定可用”。Apple官方的地区说明、Intel的条件要求和论坛中的反例共同表明，设备规格和偶发连接不能替代端到端可用性。

本项目的6GHz应维持为不计入部署保证的条件能力，而不是已验收功能。既定面板/吊顶AP形态和有线网络架构不因此失效；是否为尚不能保证使用的6GHz硬件付费，是采购决策，而不是靠一条“解锁”经验就能消除的工程风险。
