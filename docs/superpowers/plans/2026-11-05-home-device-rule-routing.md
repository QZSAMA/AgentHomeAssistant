# 同一家庭 LAN 按设备选用 OpenWrt：实施计划

> **执行说明：** 按 executing-plans 技能逐任务执行，使用下方复选框跟踪。用户已批准架构；本次交付范围是整理文档并推送，尚未操作家庭设备。所有实施步骤未执行，现场状态均为 `not_run`。

**Goal：** 在不改变家庭共同网络和普通联网路径的前提下，让少量指定终端按需使用 J3455 上的规则服务，并能手动恢复普通网络。

**Architecture：** Fusion 保留主网关、唯一 DHCP、独立普通 DNS 与控制器。Proxmox 新增单臂 OpenWrt 完整 VM；2.4GHz 共用 SSID 内按终端手工配置网关，日常 5GHz/可用 6GHz 使用另一 SSID，但仍桥接同一 LAN。

**Tech Stack：** 现有 Proxmox、OpenWrt x86-64、VirtIO、fw4/nftables、DNS 服务；OpenClash 与 Mihomo 为安装前需复核的候选组件；Fusion/Omada 与现有 AP/交换机。

## Global Constraints

- [批准版设计](../specs/2026-11-05-home-device-rule-routing-design.md)为唯一现行范围；只配置已登记的规则终端。
- 同一 LAN/网段，不新增 VLAN、PPSK 分网、家庭设备隔离或全屋合成地址段路由。
- Fusion DHCP 始终开启并作为唯一服务；普通 DNS 不依赖 J3455。
- OpenWrt 接入家庭 LAN 前关闭 DHCPv4、DHCPv6 服务及 RA；DNS 服务可保留。
- 保留宿主、存储、现有桥与物理接线，不做物理网卡直通，不同时升级网卡。
- 不承诺指定终端自动切换、不承诺未测试的 IPv6 规则覆盖；不全局关闭本地 IPv6/Thread。
- 普通设备受影响、地址冲突、出现额外 DHCP/RA 时立即断开新 VM 的虚拟网卡，保持 Fusion 普通路径。
- 不复制历史候选版本/哈希为安装事实；真实节点、订阅地址、密码及完整日志不入库。

## 文件与现场配置对应关系

| 位置 | 内容 | 修改时间 |
|---|---|---|
| `docs/validation/home-device-rule-routing.md` | 参数、设备范围、版本与检查证据、恢复用时 | 每任务记录脱敏结果 |
| `docs/home-infrastructure-register.md` | 最终采用范围与现场结果入口 | 验收后更新，不能提前写已部署 |
| 新 VM 的 `/etc/config/network` | 固定地址、实际接口、Fusion 上游、独立启动解析 | 隔离首启时 |
| 新 VM 的 `/etc/config/dhcp` | 关闭地址服务和 RA，保留 DNS | 接入家庭 LAN 前及每次组件变更后 |
| 新 VM 的 `/etc/config/firewall` | 单臂转发、受控 SNAT、关闭卸载 | 单终端普通转发试点 |
| 新 VM 的 `/etc/sysctl.d/90-home-device-routing.conf` | IPv4 转发与 redirect 状态 | 普通转发试点 |
| 规则组件私有配置 | 规则、解析、出口及局域网例外 | 普通转发通过后；不入 Git |
| Fusion / Omada 页面 | 地址池避让、现有 LAN、两组无线名称及频段 | 备份后；保留网关与 DHCP 职责 |
| 指定终端的无线配置 | 手动 IPv4、OpenWrt 网关/DNS；日常无线自动配置 | 每台单独试点 |

本计划不提供可直接套到未知现场的批量脚本。配置值来自任务 1 实际参数表；表中未取得的值保持 `not_run`，不得猜测后执行。下面的只读命令仅在已授权的现场控制台使用，本轮未运行这些设备命令。

## 任务 1：盘点、备份和普通路径基线

**输入：** 现场设备、当前网络、PVE 与存储配置。**输出：** 验收单 A/B 表和宿主外备份。**退出条件：** 地址无冲突、资源有余量、管理与普通解析不依赖规则 VM。

- [ ] 确认 Fusion、交换机和 AP 已到货型号/硬件版/固件；设备未到货则停在资料准备，不能用模拟页面代替实机验证。
- [ ] 从正常终端和 Fusion 页面记录现有 LAN/CIDR、网关、DHCP 池/保留地址、DNS 及上游；核对 Fusion 是唯一 DHCP，现有 IPv6 路由来源已记录。
- [ ] 在 PVE 控制台读取资源与网络，保存脱敏摘要：

```sh
pveversion -v
qm list
pct list
pvesm status
ip -br address
ip route
bridge link
free -h
lsblk -o NAME,SIZE,TYPE,FSTYPE,MOUNTPOINTS,MODEL
lscpu
```

- [ ] 记录 PVE 管理 IP、家庭桥和物理网卡、已有来宾与启动顺序；查明现有规则容器是否修改宿主路由、占用 DNS 端口或承接其他终端，不停用未迁移的服务。
- [ ] 选择空闲 VMID、本地 VM 存储及候选 2vCPU/2GiB/8GiB 资源；确保存储 VM、宿主与未来 HAOS 有余量，VM 存储不要求其他来宾先启动。
- [ ] 对照 Fusion 租约、静态地址登记和邻居表，分配 VM 与首台终端地址；为手动地址设置可验证的池外范围或保留/排除，不能仅凭 ping 无响应判空闲。
- [ ] 导出 Fusion/AP 配置与 PVE 来宾配置，备份相关原服务；将副本存到 J3455 之外，验证文件可读和恢复入口可访问。
- [ ] 准备管理电脑的已查重静态地址，网关/DNS 走 Fusion；通过实际 IP 访问 Fusion、PVE、存储管理页，保存本计划和应急单离线副本。
- [ ] 在普通网络记录网关、DNS、新域名解析与新连接、延迟、丢包、三次吞吐，以及 NAS/家庭控制基线；记录测试时间、位置和设备，避免后续换测点比较。

**失败处理：** 备份、资源或地址不满足则保持现网，不创建承担流量的 VM。

## 任务 2：准备安装与离线恢复材料

**输入：** PVE 版本、VM 资源、实际 CPU 能力。**输出：** 可校验的安装包及版本清单。**退出条件：** 镜像来源和兼容性可追溯，必要文件在本地与宿主外可取得。

- [ ] 从 [OpenWrt 官方下载入口](https://downloads.openwrt.org/)选择实施时支持的 x86-64 稳定发行版；记录版本、镜像类型和启动方式，确保 BIOS/UEFI 与后续 VM 设置一致。
- [ ] 下载对应镜像、官方 SHA256 清单及可用签名材料；在管理电脑核对校验值。可用 PowerShell 选择实际文件后计算：

```powershell
$RuleImagePath = Read-Host '输入已下载镜像的绝对路径'
Get-FileHash -Algorithm SHA256 -LiteralPath $RuleImagePath
```

- [ ] 从 [OpenClash 发行页](https://github.com/vernesong/OpenClash/releases)与 [Mihomo 发行页](https://github.com/MetaCubeX/mihomo/releases)核对所选版本、包格式、fw4 适配、引擎 CPU 要求；记录文件哈希与依赖。J3455 不根据“x86-64”名称就选择需要额外指令集的构建。
- [ ] 将解压后的磁盘镜像放入可访问的 PVE 本地目录，使用 `qemu-img info`读取其实际格式；导入目标只能是新 VM，不向现有物理数据盘写镜像。
- [ ] 若需扩展根分区，准备经官方校验的离线分区工具及镜像原始副本；同时准备版本匹配的依赖包，不能混装不同发行版的内核模块。
- [ ] 将版本清单、安装材料、备份与应急单复制到宿主外；断开外部访问后确认仍可找到和读取。配置中的凭据单独保存在密码管理器或受保护的运维资料中。

**失败处理：** 无法核对来源、架构或依赖时不安装该候选包，继续使用普通网络。

## 任务 3：隔离创建并安全接入 OpenWrt VM

**输入：** 参数表、已核验镜像。**输出：** 可管理、无 DHCP/RA 的单臂 VM。**退出条件：** 重启后保持固定地址与服务边界，普通终端仍只收到 Fusion 参数。

- [ ] 在 PVE 新建独立 VM，使用空闲 VMID和名称 `home-device-router`；按任务 2 确定启动方式，初始 2vCPU、2GiB 固定内存。CPU 类型须与已核验引擎匹配，暂不启用开机自启。
- [ ] 添加单张 VirtIO 网卡，接现有家庭桥，不设新的 VLAN tag；首启前勾选链路断开，记录其 MAC，不修改宿主桥或现有网卡。
- [ ] 按现场 PVE 版本的磁盘导入入口，将核验过的镜像导入新 VM 的本地存储；核对返回的磁盘属于新 VM 后挂载并设为启动盘。新 VM 不挂现有宿主或 NAS 数据盘。
- [ ] 如虚拟盘扩至 8GiB，另检查并扩展新盘的根分区与文件系统；在来宾内用 `df -h`确认有效空间，不能只看 PVE 显示的盘容量。
- [ ] 保持虚拟链路断开，通过 PVE 控制台读取默认配置：

```sh
cat /etc/openwrt_release
ip -br link
uci show network
uci show dhcp
df -h
```

- [ ] 使用实际 LAN 接口设置下表；不存在默认 `lan` 段名时先定位绑定 VirtIO 网口的实际配置，不新建重复接口。通过控制台的 LuCI 或 UCI 编辑器逐项保存并读取核对。

| 配置项 | 应用值与检查要求 |
|---|---|
| LAN 协议/地址/掩码 | 静态；任务 1 记录的 `OPENWRT_IP` 与 `HOME_MASK` |
| 默认网关 | `FUSION_IP`；不产生指回自身的默认路由 |
| 启动 DNS | 已实测可独立解析的 Fusion 普通 DNS；不指向未启动的规则组件 |
| DHCPv4 | 该 LAN 的 Ignore interface / 禁止分配开启 |
| DHCPv6、RA、NDP 代理 | VM 上对应服务关闭；不改变家庭其他设备的 IPv6 |
| DNS 监听 | 后续服务该 LAN 的查询；关闭 DHCP 不等于关闭 DNS 进程 |
| 不使用的 WAN/WAN6 | 核清后移除误绑定，确保单个 LAN 上游，不额外获取/发布默认路由 |
| 管理入口 | 设置管理员口令，仅从家庭 LAN 管理；Fusion 不新增外网端口转发 |

- [ ] 保存并在链路仍断开时重启 VM，通过控制台重新核对固定地址及 DHCP/RA 已关闭；制作此阶段配置备份。
- [ ] 连接虚拟网卡。用一台普通终端重连/续租，核对地址服务与网关/DNS仍来自 Fusion；用交换机/终端侧短时抓包检查没有来自 VM 的 DHCP Offer 或 RA，摘要入验收单。
- [ ] 管理电脑通过实际 IP访问 VM；VM 能访问 Fusion、独立解析普通域名；PVE与原服务保持原有 Fusion 路径。

**失败处理：** 发现冲突、额外地址服务或影响其他设备时立即断开新 VM 虚拟网卡，恢复其离线配置；不要关闭 Fusion DHCP。

## 任务 4：单终端普通转发与两组无线配置

**输入：** 通过任务 3 的 VM、原无线备份、首台试点终端。**输出：** 可验证的直接转发及切回普通路径。**退出条件：** 单臂回包正确、同 LAN 互访正常，其他设备参数不变。

- [ ] 在 Omada 检查两组 SSID 都映射现有家庭 LAN：`SSID_24`只启用 2.4GHz，`SSID_DAILY`启用 5GHz及实际可用的6GHz；保持已有智能家居名称/密码，不启用访客或客户端隔离。
- [ ] 验证两个名称取得相同网段的 Fusion DHCP参数，可访问同一台 NAS/家庭中枢；若跨名称不能互访，修正映射后再继续。
- [ ] 备份 VM 的 network/dhcp/firewall 配置。规则组件暂不运行，在 LuCI 防火墙的实际 LAN 区允许必要的同区转发，开启标准 IPv4 SNAT/masquerade，源范围限定现有家庭网段、目的排除真实家庭网段；核对只作用于送入 VM 并转发到上游的流量。
- [ ] 在 VM关闭软件/硬件流量卸载；设置 IPv4 转发为 `1`，`send_redirects`与`accept_redirects`在 `all`、`default`和实际 LAN接口均为 `0`。将设置持久化到表列的配置文件，重启后复查。
- [ ] 在 VM只读核对，`fw4 check`必须无语法错误，默认路由必须经 Fusion；`nft`仅有本案预期的单套转发与 SNAT：

```sh
fw4 check
ip route
sysctl net.ipv4.ip_forward
sysctl net.ipv4.conf.all.send_redirects
sysctl net.ipv4.conf.all.accept_redirects
nft list ruleset
```

- [ ] 首台手机/平板连接 `SSID_24`，进入该无线网络详情，将 IPv4设为手动，填查重后的 `CLIENT_IP`、`HOME_MASK`和网关 `OPENWRT_IP`；另将 DNS设为手动、仅保留 `OPENWRT_IP`。记录平台和菜单名称；固定/保留地址需匹配实际私有 MAC模式。
- [ ] 用真实局域网 IP验证 Fusion/PVE/NAS 可达，用普通新域名验证 DNS与外网；结合 VM计数器或短时抓包，确认对外转发源地址转换及回包经过 VM，局域网真实地址访问直接在 LAN 内完成。
- [ ] 在相同测点比较三次普通吞吐、延迟与 NAS访问；记录 CPU、温度和磁盘等待，发现影响存储服务则降低试点负载并调整资源。
- [ ] 手动切 `SSID_DAILY`，确认其 IPv4和DNS均自动、网关为 Fusion、普通新连接可用；再切回 `SSID_24`核对手动配置仍保存。记录恢复用时。

**失败处理：** 试点终端切日常网络或将原网络 IPv4/DNS恢复自动；只修复 VM，不扩大接入范围。

## 任务 5：规则组件、解析与双栈试点

**输入：** 普通转发已通过的 VM及版本清单。**输出：** 单设备规则行为和明确的应用覆盖范围。**退出条件：** 普通与指定访问分别符合规则，家庭互访正常，双栈限制如实记录。

- [ ] 对 VM做可读备份，通过 PVE控制台安装任务 2核验的组件和依赖。需要替换 DNS包时先保留原包/配置、核对依赖和恢复入口；禁止跨版本混装或全局强制覆盖冲突文件。
- [ ] 安装后再次检查 DHCPv4、DHCPv6、RA均关闭；组件升级或向导不能重新启用地址服务。普通终端继续从 Fusion获取参数。
- [ ] 在私有配置中设定规则模式：实际 LAN网段与本地名称优先直连，指定站点及必要依赖使用 `RULE-OUT`，其余默认 `DIRECT`；保留管理与节点启动解析的独立上游。
- [ ] 明确 dnsmasq与规则解析器的监听端口/上游关系，确认没有彼此转回的解析循环；不用混填两个不同 DNS来模拟主备。若采用合成地址模式，排除真实 LAN及本地名称，不修改 Fusion 全屋 DNS或静态路由。
- [ ] 核对插件旁路兼容/NAT选项，避免重复设置与任务 4冲突。重启规则服务后复查转发、DNS和防火墙，不以进程在线代替实际应用通过。
- [ ] 用普通网站和指定网站各做新查询、新连接，记录命中的规则及出口类别；覆盖页面子资源、必要UDP/QUIC和影音应用。仅保存少量脱敏结果，不上传完整日志。
- [ ] 分别核对试点 IPv4与IPv6路径、A/AAAA解析，以及启用独立解析/私有中继的应用；将“IPv4已验证、IPv6仍经普通出口”等实际情况写入验收单。不能由 IPv4成功宣布全覆盖。
- [ ] 测试 AirPlay、家庭控制、NAS发现与访问，以及已有的 HA/Matter/Thread功能；工具中保留局域网访问，检查终端系统本地网络权限。
- [ ] 对无法满足指定应用规则的设备，恢复普通路径并标 `failed`；可改用终端工具后重新验收，不修改全屋 IPv6来迁就试点。

**失败处理：** 优先让试点终端切日常网络；再在控制台恢复任务 4备份，不要求普通家庭设备变更参数。

## 任务 6：故障隔离与手动恢复演练

**输入：** 规则试点、至少一台直接使用 Fusion的对照终端、应急单。**输出：** 验收单 D/F表的证据与恢复时间。**退出条件：** 对照终端普通网络独立，试点终端能按说明切回，所有故障场景有实际记录。

- [ ] 先验证两台终端正常状态，记录网关/DNS、普通冷查询、新连接与局域网访问；对照终端不要同时启用可能改变路径的客户端工具。
- [ ] 单独停止规则服务；确认对照终端仍能建立普通新连接，再让试点终端手动切日常网络，记录成功与耗时。恢复服务后确认规则能重新使用。
- [ ] 正常停止 OpenWrt VM，重复相同检查；不改 Fusion DHCP或DNS。确认 AP仍广播时手机不会被假定已经自动切换。
- [ ] 在不影响正在写入的存储任务的维护窗口，按已有来宾顺序安全停止服务并正常关闭 J3455，重复普通网络及切回测试；同时记录 NAS/HA预期暂停，不能计为基础网络故障或隐瞒。
- [ ] 恢复宿主及必要服务后，在确认无存储网络写入/远程管理依赖的窗口，仅断开 J3455自身网线，重复检查；不要拔交换机上联或AP供电来代替此项。
- [ ] 重新接线并恢复 VM，核对唯一DHCP、DNS和规则；试点终端先确认普通网络可用，再主动切回规则配置。
- [ ] 在手机上实际打开离线应急单完成一次操作，记录各故障的预期/实际影响、恢复用时和限制；未做的项目保持 `not_run`。

**失败处理：** 普通对照终端受影响即停止扩大使用，排查其网关、DNS及现有规则容器依赖；恢复普通路径。只切回试点终端，不执行历史全屋 DHCP迁移步骤。

## 任务 7：少量设备登记、备份与交付

**输入：** 上述通过结果与限制。**输出：** 可维护的设备登记和恢复材料。**退出条件：** 每台加入设备单独验收、备份在宿主外、观察期无未解释的普通网络影响。

- [ ] 每增加一台设备登记代号、SSID、地址来源、网关/DNS、固定私有地址模式、IPv6情况、应用规则与切回方式；先通过任务 4/5的设备检查，再继续下一台。
