## 2. 交付设计

### 配置与操作说明

在 `examples/hermes-ha-lab/` 提供无凭据样例：

- Hermes 的 `HASS_URL`、`HASS_TOKEN` 环境变量模板及独立测试 profile 使用说明。
- HA 原生配置包：虚拟开关 `input_boolean.aha_lab_light`，以及只操作它的 `script.aha_lab_work_mode`。
- 虚拟开关用于模拟灯的开关状态，不宣称验证了真实灯具或 `light` 域兼容性。
- 配置通过手动合入测试实例，不覆盖已有 HA 配置；第一阶段不启用事件驱动 Agent。

实验必须使用不含真实设备的测试 HA。提示词约束、官方危险服务黑名单都不能当作实体级权限隔离。

### 只读检查工具

新增 `scripts/ha_probe.py`，独立于旧中间件运行：

```powershell
python scripts/ha_probe.py --entity-id input_boolean.aha_lab_light --json
```

接口约定：

- 从环境变量读取 URL 和 Token，不接受命令行 Token；缺少配置时不发起请求。
- 仅通过 GET 检查认证、HA 版本及指定实体状态；不执行设备控制、脚本或配置修改。
- `--entity-id` 可重复；不指定时只检查 API 和版本。
- 默认每次请求超时 5 秒、不自动重试、不跟随重定向，HTTPS 使用正常证书验证。
- 退出码：`0` 检查通过，`1` 连接／认证／API／实体检查失败，`2` 输入配置错误。
- JSON 输出包含检查范围、结果、HA 版本和逐项原因；明确范围是 `ha_rest_probe`，不是 Hermes 端到端验收。
- 不输出 Token、认证头、原始错误响应或全屋设备信息。

### 文档与验收记录

执行开始后，将设计和本计划归档到 `docs/superpowers/`，并新增接入与验收说明：

- 记录版本来源、配置步骤、执行命令、恢复及清理方法。
- 验收项统一使用 `not_run`、`passed`、`failed`，未运行不得填通过。
- 明确官方插件的服务调用成功仍需回读状态，不能直接视为设备执行成功。
- 本轮以新增文件为主，不覆盖正在编辑的网络、设备和布线台账。

## 4. 测试与完成标准

新增测试隔离放在 `tests/ha_lab/`，执行：

```powershell
python -m unittest discover -s tests/ha_lab -v
```

离线测试覆盖：

- 缺少配置、非法 URL 或实体 ID。
- 正常认证、版本读取和实体状态解析。
- 401／403、实体不存在、设备状态不可用、超时、连接失败。
- 非 JSON 或结构异常的响应、重定向拒绝。
- 文本／JSON 输出与退出码一致，任何错误路径均不泄露 Token。
- 检查器只发送 GET，不导入或启动旧中间件。

底座完成标准：上述测试通过、样例和操作说明齐全、真实联调项保持 `not_run`。旧中间件的已知问题单独列出，不宣称其全量测试通过。

## 5. 下一阶段门槛

准备真实测试环境后，再验证：

1. Hermes 发现、查询虚拟实体。
2. 文本指令开关测试实体，随后回读确认状态。
3. 执行 HA 原生脚本，核对执行后的状态。
4. HA 不可达、鉴权失败或目标不明确时，不虚构成功。
5. 停止 Hermes 后，HA 界面和原生脚本仍能工作。
