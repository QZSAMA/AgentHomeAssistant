# 同一家庭 LAN 按设备分流：验收与应急操作单

日期：2026-11-05。**方案已批准，尚未部署；本表全部现场状态为 `not_run`。** 配套：[现行设计](../superpowers/specs/2026-11-05-home-device-rule-routing-design.md) · [实施计划](../superpowers/plans/2026-11-05-home-device-rule-routing.md)。

执行边界：Fusion 始终保留唯一 DHCP及独立普通 DNS；OpenWrt 的 DHCP/RA始终关闭；两组 SSID和有线设备保持同一家庭 LAN。不执行旧单据中的全屋地址服务迁移。

## B. 设备范围登记

每台主动使用规则服务的终端单独一行。普通设备按类别抽查基础网络；没有独立家庭 IP的 Zigbee设备登记其所属网关。

| 设备代号/类别 | 接入与配置 | 规则/本地访问/IPv6/切回结果 | 状态 |
|---|---|---|---|
| 首台手机/平板 | `SSID_24`手动地址、OpenWrt网关/DNS；私有地址模式记录 | 尚未执行 | `not_run` |
| 后续指定终端 | 每新增一台复制独立记录行 | 尚未执行 | `not_run` |
| 普通手机/电脑 | `SSID_DAILY`自动，Fusion网关/DNS | 普通访问及跨SSID互访 | `not_run` |
| 智能家居网关/中枢 | 2.4GHz或有线，Fusion参数 | 本地控制、云功能、J3455停机影响分别记录 | `not_run` |
| Apple TV等有线设备 | 默认Fusion；工具能力另核 | 媒体/发现/睡眠唤醒 | `not_run` |
| PVE/存储/未来HA | 管理与启动解析走Fusion | 宿主停机时服务暂停另记 | `not_run` |

## D. 故障矩阵

每项都用**普通对照终端**测新域名解析和新连接，再测试**规则终端**按 E节恢复。已有视频继续播放不能替代这些检查。停宿主前完成存储服务安全停机，不用强制断电模拟测试。

| ID / 场景 | 普通对照终端预期 | 规则终端预期与操作 | 状态 | 实际影响/恢复时间/证据 |
|---|---|---|---|---|
| F01 正常运行 | 直接经Fusion，普通解析可用 | 普通/指定访问符合规则 | `not_run` | |
| F02 停规则服务 | 普通新查询/连接可用 | 可能失败；手动切普通路径 | `not_run` | |
| F03 停OpenWrt VM | 同上；无需变更DHCP | 外网可能不可用；手动切普通路径 | `not_run` | |
| F04 正常关闭J3455 | 同上；NAS/HA停止另记 | 外网可能不可用；手动切普通路径 | `not_run` | |
| F05 仅断开J3455网线 | 其他健康链路上的普通设备可用 | 失去该网关；手动切普通路径 | `not_run` | |
| F06 恢复VM/宿主/网线 | 普通路径保持 | 验证后主动切回，规则及解析恢复 | `not_run` | |

该矩阵不保证 Fusion、宽带、中央交换机或房间上联故障时不断网。不能将电竞房交换机断电后该房间终端掉线当作 J3455隔离失败，也不能忽略实际物理链路故障。

## E. 使用者应急操作

### E1. 首选：切换日常无线

1. 打开设备无线设置，选择已登记的 `SSID_DAILY`。AP仍广播原名称时也需要主动选择；不要等待手机必然自动换网。
2. 查看日常无线详情：IPv4为自动，DNS为自动，网关/DNS来自 Fusion。若终端客户端工具仍接管访问，先暂停它以验证普通路径。
3. 重新打开普通页面、家庭控制和NAS访问；需要时重连该无线并重新打开应用，清除终端旧解析缓存。
4. 指定网站暂时不可用属于已批准的降级范围；J3455修好前保持普通接入。整个过程不修改任何路由器的DHCP服务。

### E2. 只能使用2.4GHz时

1. 打开 `SSID_24`的网络详情，将手动IPv4恢复为自动，将手动DNS恢复为自动，两项都要改。
2. 断开并重新连接该无线，核对来自Fusion的新租约、网关和DNS。
3. 验证普通新查询、普通网站与局域网控制。记下原手动配置在受保护的运维资料位置，修复后再按登记表恢复。

### E3. 管理员处理新VM

1. 管理电脑使用Fusion普通路径，通过实际IP进入PVE/Fusion；必要时用已查重的静态管理地址，不能依赖规则DNS定位管理页。
2. 若新VM发出额外DHCP/RA或影响普通网络，先在PVE断开其虚拟网卡，再从控制台修复；**Fusion DHCP始终保持开启，OpenWrt DHCP始终关闭。**
3. 可从任务4备份恢复VM普通转发与DNS；恢复后复查没有解析/路由回环及残留规则，再验证单终端。
4. 在普通对照终端通过、VM规则与本地访问通过后，使用者主动切回规则配置。不能仅以“VM已启动”宣告修复完成。

## F. 状态与现场记录规则

- `not_run`：未做现场检查，包括只有文档核验的情况。
- `passed`：已实际验证，有时间、条件及脱敏证据，限制明确。
- `failed`：存在可复现失败，记录影响、回退动作与未解决项。
- 不预填恢复秒数、吞吐或成功率；不将方案批准视为部署验收。
- 每次故障记录：设备代号、开始/恢复时间、普通对照结果、规则终端结果、网关/DNS、IPv6情况、恢复动作及待解决项。原始敏感材料只存受保护的运维资料。
