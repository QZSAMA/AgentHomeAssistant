## 1. 记录规则

- `not_run`：尚未操作；`passed`：有实际结果和证据；`failed`：实际失败并记录原因；`not_applicable`：不适用且写明理由。
- 证据至少包含日期、客户端/服务器版本、外部网络类型、目标、实际路径和结果。截图/日志脱敏后再入仓库；密钥、token、真实账户及完整节点状态保留在私有存储。
- “官方支持”“命令示例语法检查通过”“能 ping”分别不等于组合兼容、已部署或应用可用。
- 公共 DERP 回退可能让服务能连上，但不能因此标记“国内低延迟中继通过”。

### 4.1 路径检查

在外部和家庭端分别记录脱敏结果；输出包含设备名/公网信息，不应原样发布。

```sh
tailscale version
tailscale netcheck
tailscale status
tailscale ping home-dev
```

`direct` 表示直接连接；`peer-relay` 对照实际自有节点；`relay` 记录 DERP region。`tailscale ping` 用于检查组网层路径，不代替 SSH、HTTPS、SMB 的权限和应用测试；刚建连时的探测结果也不代表稳定路径。

### 4.2 RTT、丢包和判定

路径稳定后，使用开发机**实际 Tailscale IP**采样。Linux/macOS 用 `ping -c 100 IP`，Windows 用 `ping -n 100 IP`；保留逐次数据，不能只保留平均数。示例 IP 不可替代现场分配地址。

- 超时计入丢包；正常回复 RTT 排序后，p95 采用 nearest-rank：第 `ceil(0.95 × 成功样本数)` 项，同时单独报告总发送数及丢包率。
- ICMP 被系统/网络过滤时记录原因，使用应用 TCP 连接时延作为补充；不要把组网探测成功伪装成 ICMP 测试通过。
- 建议门槛：p95 ≤80ms、丢包 ≤1%；80–120ms 标为体验待判定/降级；持续高于120ms或操作明显卡顿，不作为主要开发路径。
- 必须同时满足 30 分钟真实开发会话无异常断线，能执行/保存 notebook、保持 WebSocket，才能判定开发可用。门槛是本项目目标，不保证某地区一定达到。

### 4.3 吞吐与上传占用

在开发机临时目录生成一个非敏感测试文件，测试两端磁盘有足够空间，再从外部下载。Linux/macOS 开发机可用：

```sh
dd if=/dev/urandom of=/tmp/remote-access-test.bin bs=1048576 count=100
```

外部电脑在单独测试目录执行：

```sh
scp home-dev:/tmp/remote-access-test.bin ./remote-access-test.bin
```

记录文件字节数、耗时、实际路径、两端 CPU/网络负载；用两端可用的 SHA-256 工具对比散列，NAS 另测获准共享中的非敏感文件。只传输不会覆盖现有文件的测试名称，完成后按明确路径清理测试文件。

- 有效 Mbps = 文件字节数 × 8 ÷ 秒数 ÷ 1,000,000；不要把 MB/s 与 Mbps 混用。
- 家里到外部的吞吐目标以**同时间段家庭实测上传**和中继可用带宽较小者为基准；建议大文件达到该基准的 60% 以上后再分析是否满足实际需求，不能一律要求跑满规划的 30Mbps。
- 一边传文件一边使用 VS Code/Jupyter，记录 p95 和体感。若上传占满导致卡顿，先对后台传输限速/错峰再复测，不立即更换全部硬件。
- 若必须稳定使用高画质远程桌面，再单独测选定协议的帧率、画质和输入响应；不能用文件吞吐推算桌面体验。
