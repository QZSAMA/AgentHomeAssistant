## 2. 户型与点位假设

用户确认实际面积约100㎡，正式设计尚未出，当前只有下述相对布局。“上/下/左/右”仅指图纸方向，不推定南北。没有房屋长宽、墙体材质、门窗和家具尺寸，不能从100㎡反推网线长度或据此施工放线。

卫生间通常不单独放 AP。三面板一吊顶的数量和形态保持不变，信道、发射功率与覆盖效果以现场热力图、漫游和 HomePod/Matter 稳定性测试核验；大厅准确顶面位置、房屋尺寸、墙材与家具遮挡仍需补充。面板 AP 不装在金属设备箱内，也不藏在衣柜或床头遮挡后；大厅 AP 装在吊顶可见面，而不是吊顶腔内。

### 2.1 房间侧网络形态（每区域一主干、一设备箱）

用户已确认独立墙面网口也可以，不再要求电脑必须接 AP 本体的额外端口。每台 AP 的硬条件为 **Wi‑Fi 7、≥2.5GbE 有线回程和明确兼容的供电方式**，并按房间面板/大厅吊顶形态筛选；电脑使用的墙口/交换机接入口也应支持至少 2.5GbE。面板 AP 的额外端口只是可选便利，不是采购门槛，更不替代房间交换机。

用户最新暂定三房面板为 **EAP775-Wall ×3**，替代 EAP725-Wall 双频条件候选；大厅保留 **EAP772 ×1**。按 [EAP775-Wall 美国官网规格](https://www.omadanetworks.com/us/business-networking/omada-wifi-wall-plate/eap775-wall/#specifications)，其为 2.4/5/6GHz 三频 Wi-Fi 7，1×2.5GbE 上联，下联为 1×2.5GbE + 3×1GbE。房间不再有原 EAP725-Wall 的硬件 6GHz 缺口，但这不等于 6GHz 已获准在本户中国大陆安装地启用；地区许可、硬件/固件版本及保修仍待核。AP 下联口不取代房间交换机，电脑/Mac 仍接房间交换机；不把其 1G 口计作≥2.5G 电脑接口。

EAP775-Wall 官网列出 802.3at/bt 输入和最大 45W（含 25W PoE Out）；当前方案**不使用 AP 的下游 PoE 输出**。官网概览与规格表对 PoE Out 所需 at/bt 的表述不一致，启用前须向厂商核实具体硬件/固件版本；不能套用大厅 EAP772 的 25.4W，也不能用 `45−25=20W` 认定本机最大功耗。房间 PoE 交换机/注入器按已确认输入模式和总预算选配；无下游输出的模式/最大输入未核实前，可按 45W 上限预留并选用经确认兼容的 802.3bt 供电口，不能仅凭“PoE+”标签判定全部功能均可运行。尺寸为 172.9×91.2×41.3mm，附墙装套件、工作温度 0–40℃，仍需实物核对本地底盒、孔距、弯曲空间和散热；这些是暂定选型信息，不代表已采购或施工。

用户已选择主卧、次卧、工作室/电竞房、大厅**各一个小设备箱，中央到每箱仅一条 Cat6A，共四条主干**。箱内放交换机、电源适配器和配线；箱体可开门、可通风，不是把设备封死在墙体中。形态统一为 `中央交换机 → 房间交换机 → 箱外 AP + 墙面网口/电脑`。AP 和无线网关不藏入设备箱，尤其不放在金属箱内。两卫生间不默认增加独立回线或设备箱。

工作室上联10G，Mac Studio的10GbE口仍接工作室单台交换机；NAS/J3455和核心网络设备规划到弱电箱附近服务器机柜，未来高速NAS的10G口预留在中央，不再在工作室。主卧、次卧、大厅在拓扑v1.0按2.5G上联。**Mac↔NAS经过并共享工作室10G主干**，不再套用旧的同工作室交换机本地传输结论。房内AP/电脑各需支线，但不增加第二中央回线、独立Mac回线或大厅AP中央直连。静音由用户另行考虑，不再以无风扇选型作为连接方案定稿前提。

普通交换机不会把中央 PoE 电力传给 AP。房间侧应使用符合 AP 标准和功率要求的本地 PoE 交换机，或由本地多千兆 PoE 注入器供电；PoE 受电/透传方案只能在具体型号与预算核验后采用。房间设备依赖本地市电时，中央 UPS 不会自动保活它们，需另评估房间 UPS。箱门关闭后仍须满足散热、插头空间、线缆弯曲和断电维护要求。

### 3.2 智能设备的区域与协议

主卧、次卧、工作室、大厅以及两个卫生间都按需要规划灯光、开关、人体存在、温湿度、水浸等设备，不限于总图中的示例分支。摄像头位置单独确认，不默认每房一台或放在卧室/卫生间。

- Wi-Fi 设备连接覆盖合适的房间 AP；PoE 摄像头用支线接就近匹配的 PoE 交换机。
- Aqara Zigbee 设备连接兼容网关，再接家庭局域网；网关放大厅不代表只服务大厅。网关数量由覆盖、子设备兼容性和容量决定。
- 新增 Thread 设备类别候选，优先考虑可同时接入 Apple Home/HA 的 Matter over Thread 型号，不强制替换原有 Zigbee 方案。三间 HomePod mini 可提供 Thread 边界路由能力，目标是同一网络凭据、覆盖连通的 Thread Mesh；不能假设不同生态自动并网。
- Thread 不是 Wi-Fi，Matter 不是无线制式；电池传感器通常不转发信号，覆盖不足时评估具备 Thread 路由能力的常电设备。未来 Home Hub 未确认这些能力，不预先画为 Thread/Zigbee 网关。

各区域候选类别、两层 Mermaid 图与控制关系见 [智能家居拓扑图](smart-home-topology.md)。

旧版README、Code Wiki和设备清单把部分绿米、欧瑞博、Mac Studio和未来NAS混合标为“已接入”或“待购”，这些旧标签不作为采购/部署证据。**不包括用户本次明确确认的既有J3455 NAS、Proxmox及代理/转发服务**，后者按用户说明记录为已有在用；硬盘健康/备份、HA部署与其他设备的实际验收仍分别核实。

## 4. 网络架构

### 4.1 已定物理拓扑 v1.0

本版固定连接关系、设备位置及目标速率，不等于已采购、部署或完成施工图。具体型号、静音、现场尺寸/走线路径及UPS容量在实施阶段落实；用户暂缓静音决策不改变下图，也不自动恢复旧A/B组合。

```text
入户光纤
   │
   ▼
ISP 光猫（优先桥接）
   │  PPPoE / ISP VLAN / IPv6 参数由运营商确认
   ▼
AC：主路由器/网关
   │  NAT、防火墙、DHCP、VLAN、IPv6、远程访问策略
   ▼
TP-Link 管理型 2.5G/10G 中央交换机（弱电箱附近服务器机柜，Omada方向）
   ├── 1×Cat6A / 2.5G → 主卧箱交换机 → AP-MASTER（EAP775-Wall，箱外 Wi-Fi 7 面板）+ 墙口/电脑
   ├── 1×Cat6A / 2.5G → 次卧箱交换机 → AP-SECOND（EAP775-Wall，箱外 Wi-Fi 7 面板）+ 墙口/电脑
   ├── 1×Cat6A / 10G → 工作室单台交换机（型号待选）→ Mac（10G）+ AP-STUDIO（EAP775-Wall，Wi-Fi 7 面板）+ 电竞电脑
   ├── 机柜内网线 / 1G → 现有 J3455（Proxmox / NAS / 代理转发容器）
   ├── 机柜内链路 / 10G预留 → 未来高速NAS（未购）
   ├── 1×Cat6A / 2.5G → 大厅箱交换机 → 顶面支线 → AP-HALL（EAP772，Wi-Fi 7 吊顶）→ Wi-Fi → 未来 Home Hub
   └── Omada 控制器（硬件或软件，具体型号待选）
```

完整Mermaid总图与端口表见[全屋网络拓扑v1.0](network-topology.md)。核心交换设备/NAS规划放弱电箱附近服务器机柜，Mac留工作室；AP与无线网关在箱外，服务器不塞薄型房间箱。静音由用户另行考虑，柜体/散热及设备型号仍须落实但不阻挡拓扑定稿；未执行搬迁。

这里的 AC 已按用户说明解释为主路由器/网关。无线控制器若单独存在，只负责 AP、SSID、漫游和 VLAN 的管理，应作为 LAN 终端接入交换机，不能串在光猫和交换机之间。光猫无法桥接时，需要记录双 NAT 或 DMZ 方案，并重新验证 IPv6、入站访问、Home Assistant 远程访问和端口转发。

光猫负责运营商 PON 光接入与注册认证；主路由可以在光猫桥接后接管路由功能，但普通 AC/主路由不能替代光猫的光接入功能。普通 SFP 光口不等于 PON 光猫；只有运营商认可且完成兼容认证的集成设备/模块才可能合并。

### 4.2 设计约束与布线要求

- 四个主要区域各一条 Cat6A 实芯铜线星型回中央柜；AP 通过本房间交换机有线回程，不依赖无线 Mesh。Thread Mesh 是另一套低功耗网络，不与 AP 无线回程混为一谈。
- 主干分别编号 `TRUNK-MASTER`、`TRUNK-SECOND`、`TRUNK-STUDIO`、`TRUNK-HALL`，从箱内交换机到 AP/墙口/终端的支线单独编号；不使用 CCA 线。可预留空管、牵引线和维修余量，不再默认增加第二条入房主干。
- AP 采购验收逐项核对 Wi‑Fi 7、≥2.5GbE 上联、PoE 标准和最大功耗；三房必须面板、大厅必须吊顶形态，不再强制额外客户端口。面板底盒/孔距/深度、散热与遮挡，以及大厅顶面安装件、维护可达性与本地支线分别验收。电脑墙口、房间交换机接入口和上联另行核对 ≥2.5GbE 能力。
- 四个主要区域均预留可开门维护的小设备箱放房间交换机和电源；不是封墙。无风扇不等于无需通风，工作室 10G 箱须特别核算满载温度，AP/无线网关均在箱外。
- 中央机柜核算四房下联、网关、控制器、J3455、未来NAS预留，共8连接且另留余量；工作室和未来NAS各需10G，多台机柜交换机互联另占端口，只有实际受电设备需PoE。
- 工作室单台交换机需上联/Mac两个同时可用10G口，AP/电竞电脑另占≥2.5G口，共4连接，建议再留10G余量；NAS/J3455不重复计入房间。SFP+不等于原生RJ45，模块兼容/30m/温度单独核验；静音由用户考虑，不再限定必须无风扇才可定稿拓扑。
- 对中央和各房间 PoE 交换机分别核算预算：`实际由该交换机供电的设备最大功耗之和 × 1.3`；另核对每口功率。AP 的 PoE+ / PoE++ 要求和北美硬件版本下单前查官方数据表，普通交换机不能透传中央 PoE 电力。
- 旧草案的 `400×300×100mm` 弱电箱不是已确认尺寸，不能据此直接锁定设备或断言所有箱体都须更换。中央柜和房间小箱分别按最终设备、适配器、散热与弯曲半径实测；装不下大型交换机时再选较大通风柜或另设设备位。
- NAS、Mac和全屋网络后备供电目标先按至少1小时规划；按中央柜、工作室Mac/网络及其他三房分区核UPS/合规后备回路，必要机柜排风也纳入。普通网线不把中央UPS供电传给Mac或房间交换机。按实测功耗和厂家续航曲线选容量/型号，低电量有序关机并测试恢复；柜体不能为隔音密封散热，Mac不移入机柜。
- HomePod mini 通过房间 Wi-Fi 入 LAN，并可承担 Thread 边界路由角色。未来 Home Hub 按用户意向通过大厅 AP 的 Wi-Fi 接入；这个设计意向不等于其正式产品规格已经确认。
- 安装地区为中国大陆，按用户偏好继续列美国版/美国 Amazon 及 6GHz 候选；地区许可、固件功能和跨境保修未验证，不据销售规格认定本户已可用。

当前只有一套布局：**Mac 留工作室；NAS/J3455 与核心网络设备放弱电箱附近服务器机柜**，连接关系和速率按拓扑v1.0定稿。静音由用户另行考虑；正式平面图未出，散热、承重、进排风、门开启和维护空间仍须设计，普通通风柜不等于隔音柜。采购品牌排除小米/米家、华为，网络仍为 TP-Link/Omada 方向。

停电保活已从可选预算变为明确需求：NAS、Mac、全屋网络至少1小时目标。UPS数量/容量、Mac实际负载、房间供电与柜体主动散热一并核算；先核厂家负载续航曲线，再做断电和低电量有序关机验收。

### 4.4 逻辑网络与 Apple Home/HA

第一阶段把 HomePod、Apple Home/Matter、Aqara 网关、Home Assistant 和主要智能设备放在同一个可信网络，先完成配网和端到端控制。第二阶段再考虑管理、主网、IoT、访客 VLAN；一旦分 VLAN，必须配置并验收双向 mDNS/Bonjour、IGMP snooping、控制器到 HA/设备的 ACL 和 HomePod/Matter 配网流程。智能家居 2.4GHz 设备需保留兼容 SSID，不能只启用 6GHz 或 WPA3-only。

Home Assistant 是设备编排和自动化核心，Apple Home 是家庭交互与生态入口。优先使用 HA 的 HomeKit Bridge 把已验证设备暴露到 Apple Home，并根据 Aqara/空调型号选择 Matter、HomeKit、Zigbee 或厂商集成；不能仅凭品牌名称保证兼容。

HA、Apple Home 控制器和 Thread 边界路由器角色不同，都不能泛化为必须串联的数据转发路径。Matter 多管理员与 HomeKit Bridge 按设备支持情况选择；未来 Home Hub 不自动替代 HA、Aqara Zigbee 网关或 Mac 模型服务。

## 5. Mac Studio 与模型部署计划

### 5.1 硬件约束

用户已明确采购目标为 **Mac Studio M5 Ultra，512GB 统一内存 + 4TB 内置 SSD**：512GB 是统一内存，不是硬盘容量；4TB 是内置 SSD 容量，不再保留“至少2TB/4TB优先”的待选建议。内存/SSD 容量需求已确认，不等于该配置的官方可购 SKU 或购买状态已核实；下单前仍核验对应地区供应与报价。

模型权重按既有调研页面容量粗算约397GB，不等于实际运行内存占用或项目总磁盘需求。4TB SSD 还需为系统、运行时、缓存、视频素材/中间文件和开发数据预留空间；内存并发预算与存储/备份预算分别核算。外接存储、NAS 与备份容量仍另行评估，不因内置4TB而视为已购买或已落实备份。

用户确认 Mac Studio 使用 10GbE 网口，接工作室 10G 交换机。原生运行 MLX/MLX‑VLM/llama.cpp 等 Apple Silicon 服务；HA 主机独立性优先评估现有 J3455 的配置、存储与稳定性，同机或其他独立主机也仍是候选，不记为已部署。不能假设 Linux 容器直接获得 Metal/MLX GPU。所有服务先限制为局域网受控 API，工具调用采用白名单并记录审计日志。

J3455已知为16GB内存、10TB存储、千兆网口、Proxmox，已有非官方群晖NAS和家庭代理/数据转发容器；它不是空闲服务器，不能直接重装或把现有服务写为尚未部署。HA如复用其Proxmox，应先核空闲资源、磁盘健康/备份与宿主故障影响；独立HA主机仍为评估选项。10TB的盘数、原始或可用容量、冗余及备份尚未确认；现有千兆网口不会因上层10G网络而变成10G NAS。NAS/J3455规划放中央服务器机柜，Mac留工作室。
