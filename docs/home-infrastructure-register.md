### 2.1 区域侧网络形态（每区域一主干；仅电竞房/大厅设箱）

用户最新确认**主卧/次卧不需要设备箱或独立交换机，各一台 Wall AP 即可，其四个下联口用于电脑/有线设备**。每台 AP 的硬条件为 **Wi‑Fi 7、≥2.5GbE 有线回程和明确兼容的供电方式**；两卧室依 EAP775-Wall 的实际端口分配，只有一个 2.5G 下联，另三个为 1G。电竞房电脑/Mac 与 AP 仍并列接交换机，不据此改接 AP 或恢复第二台交换机。

用户暂定三房面板为 **EAP775-Wall ×3**，替代 EAP725-Wall 双频条件候选；大厅保留 **EAP772 ×1**。按 [EAP775-Wall 美国官网规格](https://www.omadanetworks.com/us/business-networking/omada-wifi-wall-plate/eap775-wall/#specifications)，其为 2.4/5/6GHz 三频 Wi-Fi 7，1×2.5GbE 上联，下联为 **1×2.5GbE + 3×1GbE**。两卧室 AP 的下联端口在用户设备量范围内代替独立房间交换机，需要2.5G的电脑优先用唯一2.5G口；其他三口不能计为≥2.5G接口，有线下联与Wi-Fi对外共享2.5G上联。AP重启或失电也会影响接在其上的有线设备。三房硬件6GHz规格不等于本户中国大陆安装地许可，地区许可、硬件/固件版本及保修仍待核。

EAP775-Wall 官网列出 802.3at/bt 输入和最大 45W（含 25W PoE Out）；当前方案**不使用 AP 的下游 PoE 输出**，但两卧室下联口正常用于数据。官网概览与规格表对 PoE Out 所需 at/bt 的表述不一致，启用前须向厂商核实具体硬件/固件版本；不能套用大厅 EAP772 的25.4W，也不能用 `45−25=20W` 认定本机最大功耗。两卧室由中央两个兼容2.5G PoE口供电，电竞房面板由ES210XPP-M2供电；无下游输出的模式/最大输入未核实前，可按每台45W上限、乘1.3预留并选用经确认兼容的802.3bt供电口，中央两台保守预算合计 **117W**，其他受电设备另加。不能仅凭“PoE+”标签判定全部功能均可运行。尺寸为172.9×91.2×41.3mm，附墙装套件、工作温度0–40℃，仍需实物核对本地底盒、孔距、弯曲空间和散热；不是已采购或施工记录。

最新拓扑保留**每区域一条Cat6A，共四条主干；只有电竞房/大厅各一个小设备箱和交换机**。两卧室形态为 `中央PoE交换机 → Wall AP → AP下联电脑/有线设备`；电竞房/大厅形态为 `中央交换机 → 房间交换机 → 箱外AP + 有线设备`。箱内放交换机、电源适配器和配线，箱体可开门、可通风，不封墙；AP和无线网关不藏入设备箱，尤其不放金属箱内。两卫生间不默认增加独立回线或设备箱。

拓扑v1.2保持**四条区域主干统一2.5G**。工作室/电竞房只用一台 **ES210XPP-M2**：10G RJ45接Mac Studio，10G SFP+接未来高速NAS；NAS须具备兼容的10G SFP+接口，同柜/相邻通风设备位可采用经两端兼容性核验的DAC短线。未来高速NAS与已有J3455均规划在电竞房箱外通风存储设备位，不再预留中央NAS接入口；这是位置规划，不表示已购买NAS或已迁移J3455。

ES210XPP-M2的8个2.5G口全部分配给中央上联、两台PC、Mac Mini、J3455、有线Apple TV、投影仪和EAP775-Wall，**十个物理接口全部占用，零备用口**。PC当前1G、计划升级2.5G；Mac Mini与J3455当前1G；Apple TV有线速率和投影仪速率按具体型号，不默认都是千兆。同交换机、同VLAN的Mac↔高速NAS以及Apple TV↔J3455本地传输不经过中央主干；其他房间访问、互联网访问等经过该主干的流量共享2.5G。跨VLAN若需上送网关路由，不能再承诺上述本地不占上联。NAS自身网口、磁盘和并发仍是独立瓶颈。

两卧室AP到电脑/终端、电竞房/大厅交换机到AP/终端仍需本地短线或支线，不增加第二中央回线、独立Mac回线或大厅AP中央直连。用户此前提出“大厅交换机再连主卧/次卧面板AP”的汇聚方案未采纳，当前两卧室AP直接星型回中央。静音由用户另行考虑，不再以无风扇选型作为定稿前提。

两卧室AP经各自主干由中央PoE直接供电，网络保活并入中央UPS负载，不设两卧室独立网络UPS点；电脑、HomePod等仍按各自市电另核。普通交换机不会把中央PoE电力传给下级AP，故电竞房/大厅使用本地兼容PoE交换机，按自身市电与UPS/合规后备回路保活。PoE受电/透传只能在具体型号与预算核验后采用；两个房间箱关门后仍须满足散热、插头空间、线缆弯曲和断电维护要求。

### 3.2 智能设备的区域与协议

主卧、次卧、工作室、大厅以及两个卫生间都按需要规划灯光、开关、人体存在、温湿度、水浸等设备，不限于总图中的示例分支。摄像头位置单独确认，不默认每房一台或放在卧室/卫生间。

- Wi-Fi设备连接覆盖合适的AP；PoE摄像头用支线接有余量的中央/大厅匹配PoE交换机，两卧室不再有独立交换机，电竞房零备用且不使用AP下游PoE。
- Aqara Zigbee 设备连接兼容网关，再接家庭局域网；网关放大厅不代表只服务大厅。网关数量由覆盖、子设备兼容性和容量决定。
- 新增 Thread 设备类别候选，优先考虑可同时接入 Apple Home/HA 的 Matter over Thread 型号，不强制替换原有 Zigbee 方案。三间 HomePod mini 可提供 Thread 边界路由能力，目标是同一网络凭据、覆盖连通的 Thread Mesh；不能假设不同生态自动并网。
- Thread 不是 Wi-Fi，Matter 不是无线制式；电池传感器通常不转发信号，覆盖不足时评估具备 Thread 路由能力的常电设备。未来 Home Hub 未确认这些能力，不预先画为 Thread/Zigbee 网关。

各区域候选类别、两层 Mermaid 图与控制关系见 [智能家居拓扑图](smart-home-topology.md)。

### 4.2 设计约束与布线要求

- 四个主要区域各一条Cat6A实芯铜线、2.5G主干星型回中央柜；两卧室主干直达Wall AP并传PoE，电竞房/大厅主干接房间交换机再有线回程至AP，不依赖无线Mesh。Cat6A保留后续升级条件，但当前区域主干不记为10G；Thread Mesh是另一套低功耗网络。
- 主干分别编号 `TRUNK-MASTER`、`TRUNK-SECOND`、`TRUNK-STUDIO`、`TRUNK-HALL`，两卧室Wall AP下联至终端、电竞房/大厅交换机至AP/终端的支线单独编号；不使用CCA线。可预留空管、牵引线和维修余量，不默认增加第二条入房主干。
- AP采购验收逐项核Wi‑Fi 7、≥2.5GbE上联、PoE标准和最大功耗；三房面板/大厅吊顶形态固定。两卧室各需EAP775-Wall下联1×2.5G+3×1G，实测电脑口与AP重启故障边界；不把四口全部写成2.5G。底盒/孔距/深度、遮挡与大厅顶面安装件/维护可达性分别验收，电竞房有线终端仍接交换机。
- 仅电竞房/大厅预留可开门维护小设备箱放交换机和电源；两卧室取消箱/交换机，不封墙。无风扇不等于无需通风，电竞房ES210XPP-M2须核满载/PoE温度；AP/无线网关放开放位置，Mac/NAS/J3455在箱外通风设备位。
- 中央核算网关、两卧室Wall AP、电竞房/大厅交换机，共5连接；Omada软件控制器复用J3455在电竞房交换机上的既有1G接入口，不另占中央端口。建议至少8×2.5G RJ45留3口余量，10G非必需；至少两口匹配Wall AP PoE及两台保守117W预算。NAS/J3455不重复计中央。
- 电竞房单台ES210XPP-M2：1×10G RJ45给Mac、1×10G SFP+给未来高速NAS，8×2.5G铜口为中央上联/PC×2/Mac Mini/J3455/有线Apple TV/投影仪/EAP775-Wall，十口全占、零备用；新增有线设备需重新设计，不默认借AP端口补位。PC现1G/计划2.5G，Mac Mini/J3455现1G，Apple TV/投影仪按实。NAS须具备兼容10G SFP+接口，近距离DAC须核两端兼容和长度；SFP+不等于原生RJ45，若改用铜模块需另核兼容、距离、温度和功耗。
- 对中央、电竞房和大厅PoE交换机分别核预算：`实际供电设备最大功耗之和 × 1.3`，另核每口功率。两卧室AP由中央PoE直接供电；AP的at/bt输入和北美版本下单前核官方数据表，普通交换机不能透传中央PoE电力。
- 旧草案的 `400×300×100mm` 弱电箱不是已确认尺寸，不能据此直接锁定设备或断言所有箱体都须更换。中央柜和房间小箱分别按最终设备、适配器、散热与弯曲半径实测；装不下大型交换机时再选较大通风柜或另设设备位。
- NAS、Mac和全屋网络后备供电目标仍按至少1小时规划；按中央（新增两卧室AP PoE负载）、电竞房Mac/ES210XPP-M2/未来NAS/J3455、大厅交换机/AP三处重算UPS/合规后备回路及必要排风，**取消两卧室独立网络UPS点**。中央PoE可保活直连Wall AP，但不向Mac/HomePod/电脑或普通房间交换机自动供电；控制节点按所需停电功能另核。按实测功耗和厂家续航曲线选容量/型号，低电量有序关机并测恢复；Mac/NAS/J3455不塞小箱，迁移尚未执行。
- HomePod mini 通过房间 Wi-Fi 入 LAN，并可承担 Thread 边界路由角色。未来 Home Hub 按用户意向通过大厅 AP 的 Wi-Fi 接入；这个设计意向不等于其正式产品规格已经确认。
- 安装地区为中国大陆，按用户偏好继续列美国版/美国 Amazon 及 6GHz 候选；地区许可、固件功能和跨境保修未验证，不据销售规格认定本户已可用。

### 4.4 逻辑网络与 Apple Home/HA

第一阶段把 HomePod、Apple Home/Matter、Aqara 网关、Home Assistant 和主要智能设备放在同一个可信网络，先完成配网和端到端控制。第二阶段再考虑管理、主网、IoT、访客 VLAN；一旦分 VLAN，必须配置并验收双向 mDNS/Bonjour、IGMP snooping、控制器到 HA/设备的 ACL 和 HomePod/Matter 配网流程。智能家居 2.4GHz 设备需保留兼容 SSID，不能只启用 6GHz 或 WPA3-only。

Home Assistant 是设备编排和自动化核心，Apple Home 是家庭交互与生态入口。优先使用 HA 的 HomeKit Bridge 把已验证设备暴露到 Apple Home，并根据 Aqara/空调型号选择 Matter、HomeKit、Zigbee 或厂商集成；不能仅凭品牌名称保证兼容。

HA、Apple Home 控制器和 Thread 边界路由器角色不同，都不能泛化为必须串联的数据转发路径。Matter 多管理员与 HomeKit Bridge 按设备支持情况选择；未来 Home Hub 不自动替代 HA、Aqara Zigbee 网关或 Mac 模型服务。

### 5.3 语音和 Apple Home 链路

用户已确认**Siri/Apple Home基础控制与本地模型自由对话都要做，但具体方案尚未决定**。HomePod/Siri不会自动把本地模型当后端；HA Assist + 本地识别/合成 + planner只是待验证实现方向。收音/唤醒终端、控制权限、播报与多房间体验需另做PoC，AirPlay音频输出不等于开放HomePod麦克风输入，不提前锁定或加购语音终端。Omni音频能力仍属实验，不作为家庭基础控制的前置依赖。
